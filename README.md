# XXVI

Входящие → флоу. Задачи приходят из источников, человек берёт одну в работу, и
она едет по флоу, стадии которого работают агенты по ACP.

Канбана здесь нет намеренно: между «пришло» и «делается» не остаётся доски, на
которой карточка лежит и ждёт, пока кто-нибудь её передвинет.

## С чего начать чтение

- [docs/system.md](docs/system.md) — формализация: что такое стадия и переход,
  при каких условиях карточка едет дальше, какой агент подбирает её на каждой
  стадии, что может источник и что проверяется при сохранении флоу;
- [docs/poc.md](docs/poc.md) — границы первой версии и что сознательно отложено;
- [docs/release.md](docs/release.md) — как выпускается версия и чем подписана.

Документы написаны до кода и остаются местом, где записаны решения.

## Как устроено

```
internal/model    домен: карточка, флоу, агент, источник. Ни базы, ни процессов
internal/store    одна SQLite: реестры, карточки, положение на флоу, сессии
internal/engine   движок флоу: одна точка входа на стадию, три пути к ней
internal/acp      агенты по протоколу: сессии, политика инструментов, вопросы
internal/inbox    источники, правила, демо-плагин
internal/app      сборка, примеры на первый запуск, API для фронта
frontend          Solid + TypeScript, биндинги генерирует wails3
```

Движок ничего не знает про ACP: работа стадии приходит к нему через интерфейс
`engine.Runner`. Настоящая реализация запускает агентов, тестовая записывает, о
чём её попросили, — поэтому весь маршрут проверяется без единого процесса.

## Запуск

Нужны Go 1.25+, Node.js и [wails3](https://v3.wails.io/).

```sh
wails3 dev          # разработка, с горячей перезагрузкой фронта
wails3 build        # сборка приложения
```

Версия написана в `version.go`, и `wails3 task version:set VERSION=x.y.z`
переписывает её разом во всех сборочных файлах, где она названа ещё раз; тест
рядом падает, когда они разошлись.

Данные лежат в `~/Library/Application Support/XXVI` (macOS): база `xxvi.db` и
папки демо-источников. На пустой базе первый запуск создаёт агента, два флоу и
два источника с примерами — досеивать то, что уже поправили, приложение не
будет.

### Проекты

Проект — место, где идёт работа: папка на этой машине, выбранная системным
диалогом (набрать путь руками тоже можно). Карточка выбирает одно из
них при «Сделай» или на своей панели, и там открываются агент, терминал и
заметки её ленты — одно место вместо четырёх настроек. Без проекта карточка
получает свою пустую папку, и для задачи с чистого листа это верный ответ.

Про git приложение не знает ничего: агент работает прямо в папке, а ветку
заводит сам, если стадия его об этом просит.

### Обновление

Приложение заменяет себя версией новее: спрашивает подписанный манифест по
адресу, вкомпилированному внутрь, и ставит только то, что сошлось с ключом, с
которым собрано. Само оно только проверяет — скачивание ждёт кнопки на экране
«Обновление». Что переживает перезапуск, лежит в `updates.json` рядом с базой.

### Лента

Карточка, взятая в работу, разворачивается в **ленту** — полосу экранов, по
которой едешь вбок. Каждый выполненный шаг дописывает справа свои экраны: ход
агента, заметки в папке карточки, встроенный браузер на адрес, который записала
стадия. Когда шаг заканчивается, лента сама перелетает на следующий экран — но
если фокус увели руками, она не дёргает, а предлагает «Дальше →».

Экраны объявляются на стадии в редакторе флоу, набор видов замкнут, а в ссылке
можно подставить свойство карточки: браузер на «{Превью}» открывает то, что
записала стадия проверки.

Голую прокрутку лента себе не забирает: колесо и два пальца принадлежат тому,
что под курсором, — странице в браузере, потоку агента, терминалу. Вбок,
впрочем, никто из них не прокручивается, поэтому два пальца вбок доезжают до
самой полосы и ведут её между экранами; исключение — встроенный браузер, где
страница забирает жест себе.

Всё остальное — отдельно: `←/→` между экранами, `↑/↓` или `Cmd`+колесо между
лентами, `R` и `F` меняют ширину экрана, `Esc` уводит из ленты. С модификатором
те же стрелки работают и когда набираешь в заметках.

### Уведомления

Вопрос агента приходит системным уведомлением с вариантами прямо на нём —
ответить можно там, в панели «Требуют внимания» или на карточке: это один и тот
же вопрос. На macOS уведомления работают только из собранного `.app`: без
бандла система их не просто запрещает, а роняет процесс, поэтому при запуске
бинаря напрямую они выключаются с записью в лог. Ничего при этом не теряется —
уведомление всегда лишь вторая дорога к ответу.

### Агенты

Настоящие ACP-адаптеры: `claude`, `codex` и произвольная ACP-команда. Экран
«Агенты» отвечает, запустится ли агент на этой машине, — раньше, чем это
выяснится на карточке. Оба вендорских адаптера публикуются в npm:

```sh
npm install -g @agentclientprotocol/claude-agent-acp
npm install -g @agentclientprotocol/codex-acp
```

Не установлены, но есть Node.js — запустятся через `npx`, только первый раз
дольше.

## Тесты

```sh
go test ./internal/...
```

Отдельно — проверка с живым агентом. Она запускает настоящий адаптер, поэтому
требует установленного агента и залогиненной учётки и стоит столько же, сколько
один ход:

```sh
go test -tags liveagent ./internal/app/ -run Live -v
```

Остальное про запуск агента проверяется подставным исполнителем; эта — про то,
что карточка действительно проезжает флоу.
